# Agent-First Setup Engine

WeekendStack now supports a declarative setup flow alongside the interactive installer.

The user-facing flow is now:

1. `install.sh`
   - bootstrap host prerequisites and repo checkout
2. `setup.sh`
   - choose services and generate/apply desired state
3. `configure.sh`
   - collect secrets and finish manual external integrations like tunnel auth, Cloudflare, Git SSH, and Coder templates

## Canonical Files

- `weekendstack.config.json`
  - Desired state for the install
  - Safe for humans or agents to edit
- `.env`
  - Generated runtime artifact
  - Compatibility layer for the existing compose/setup tooling
- `setup-plan.json`
  - Machine-readable plan generated by `setup.sh --plan`
- `setup-state.json`
  - Machine-readable install state generated after apply/repair flows

## Core Commands

```bash
# Show the computed plan from an explicit config
./setup.sh --plan --config weekendstack.config.json

# Emit plan JSON for an agent
./setup.sh --plan --config weekendstack.config.json --json

# Apply declarative config without interactive prompts
./setup.sh --apply --config weekendstack.config.json

# Add profiles or optional services to an existing config, then apply
./setup.sh --add ai,monitoring
./setup.sh --add-service paperclip,open-webui

# Inspect host health and config drift
./setup.sh --doctor --json

# Repair deterministic infra drift only
./setup.sh --repair --scope infra
./setup.sh --repair --scope cache
./setup.sh --repair --scope network
./setup.sh --repair --scope auth
./setup.sh --repair --scope storage

# Finish human-owned configuration after setup/apply
./configure.sh --all
./configure.sh --status
./configure.sh --tunnel-auth
./configure.sh --cloudflare
./configure.sh --git-ssh
./configure.sh --coder-templates
```

## One-Line Installs

The human bootstrap remains `install.sh`. For non-interactive installs, provide a hosted config file:

```bash
curl -fsSL https://raw.githubusercontent.com/weekend-code-project/weekendstack/main/install.sh | \
  sudo bash -s -- --config-url https://example.com/weekendstack.config.json
```

`install.sh` downloads that config into the repo root and then runs `setup.sh --apply --config weekendstack.config.json`.
After apply, agents or setup summaries should prompt the user to run `./configure.sh --all` when tunnel or development integrations are still pending.

## Service Catalog

`tools/env/mappings/service-metadata.json` is now the canonical catalog for:

- profile membership and optional-service activation
- access exposure by mode
- first-run/manual follow-up classification
- health metadata
- resource estimates used by planning and doctor output
- cleanup and authoring defaults

Use `tools/setup/scaffold-service.sh` plus `docs/add-service.md` to add new services.

## Repair Scope

Repair intentionally avoids app-specific onboarding state. It only reconciles deterministic infrastructure:

- generated config artifacts
- compose/custom-profile drift
- registry cache and Docker mirror state
- tunnel/local-network derived config
- Traefik auth assets
- required directories/volumes
- container health for the selected stack
